# BillShield US — план команды из двух человек до 12:00

**Воскресенье, 15 ноября 2026 года. Время Актобе (UTC+5).** Публичная версия со всем сценарием — к **07:35**. С **08:15** команда исправляет ошибки и готовит материалы. Капитан отправляет работу к **11:30**. До дедлайна в **12:00** остаётся полчаса резерва.

## Что должно получиться

**Трек Money.** Пользователь — застрахованный взрослый 25–45 лет в США. Он заплатил на приёме, получил счёт от клиники и хочет выяснить, учли ли его платёж. BillShield сверяет один визит, помогает задать вопрос нужной организации и показывает, исправилась ли сумма в следующем счёте.

Жюри открывает английский интерфейс, нажимает **Try a sample**, меняет любую сумму или дату и видит пересчёт. Тот же сценарий работает с пустой формой и собственными значениями. Для гостя доступны первая сверка, подготовка к звонку, сохранение ответа и проверка следующего счёта. В одном браузере можно сохранить несколько семейных визитов, присвоить каждому название и вернуться к нему по году. Для ввода достаточно дат, сумм и подтверждения, что документы относятся к одному пациенту, поставщику и визиту. Имя, диагноз и номер страхового полиса для расчёта не нужны.

Первым делом передай напарнику формат данных и один пример. Вход — дата и доля пациента из EOB, дата и остаток счёта, сумма и дата зачисления платежа. При доле $600, платеже $150 до выпуска счёта и выставленных $600 твой модуль возвращает остаток $450, расхождение $150 и адресата **provider billing**. По этому примеру напарник сразу собирает экран. Форму организаторов отправляет официальный капитан команды.

**Напарнику для работы над интерфейсом.** На странице `/try` подключи [типы входа и результата](src/lib/bill-types.ts) и [учебный пример](src/samples/bill-sample.ts). Кнопка **Try a sample** вызывает `createBillSample()`. Поле `first` заполняет начальную форму, `call` и `next` содержат учебные данные для следующих шагов. Деньги в контракте передаются в центах, даты в формате `YYYY-MM-DD`, неизвестные значения — `null`. При редактировании сохраняй локальный ID каждой квитанции.

Функции можно вызывать непосредственно из компонента формы при изменении данных.

```ts
import { checkBill } from "@/lib/bill-check";
import { compareNextStatement } from "@/lib/bill-follow-up";
import { createBillSample } from "@/samples/bill-sample";

const { first, call, next } = createBillSample();
const initial = checkBill(first);                         // 45000 cents expected
const followUp = compareNextStatement(first, next, call); // 5000 cents to clarify
```

Для денежных полей используй `parseUsdCents` и `formatUsdCents` из [bill-money.ts](src/lib/bill-money.ts). При `needs_info` покажи `call.question`. При `matches` проверь `call.action` — платёж после даты счёта может требовать проверки текущего остатка в кабинете клиники. В повторной сверке `current.differenceCents` относится к документам, `promiseDifferenceCents` — к обещанию клиники. Значение `null` означает, что сравнение недоступно. Если платежи прежние, опусти `next.payments`. При изменении передай полный список квитанций с их исходными ID.

**Печатный отчёт.** После деморазблокировки выведи один [PrintableBillReport](src/components/PrintableBillReport.tsx) с данными открытого дела. Пропусти `call` или `next`, если пользователь ещё не прошёл соответствующий шаг. Метка `sample` предназначена для учебных данных. Кнопка печати встроена. Отдельный пример доступен по `/report/sample`.

```tsx
import { PrintableBillReport } from "@/components/PrintableBillReport";

// В компоненте, где уже есть состояние дела и признак демодоступа:
return unlocked ? <PrintableBillReport first={first} call={call} next={next} /> : null;
```

## Что именно реализовать

### 1. Первая сверка

- Пользователь вводит дату и долю пациента из окончательного **Explanation of Benefits (EOB)**, полный остаток по этому визиту со счёта клиники, дату счёта и собственные платежи с датами их зачисления клиникой. Рядом с полями дайте подсказки **Patient responsibility** и **Balance for this visit**. Страховая указывает долю пациента в EOB, а факт его личной оплаты подтверждается отдельно. Если страховая пересчитала долю пациента после выпуска счёта, предложите запросить актуальный счёт. [Руководство CMS по EOB](https://www.cms.gov/initiatives/your-patient-rights/medical-bill-rights/get-help/guides-resources/read-explanation-benefits)
- Считай в целых центах. **Расчётный остаток на дату счёта = доля пациента по EOB − собственные платежи, зачисленные к этой дате по этому визиту.** Разница равна выставленному остатку минус расчётный. Положительную разницу показывайте как сумму к уточнению. Если счёт ниже расчётного, покажите обе суммы и предложите проверить корректировку. Если платежи превысили долю пациента, предложите уточнить остаток в пользу пациента.
- Дайте выбрать **I’m not sure**. При другом поставщике, сводном семейном счёте, наличии только минимального взноса или неизвестной разноске платежа предложите запросить детализацию. Если платёж прошёл позже выпуска, покажите его дату отдельно и предложите проверить текущий остаток в кабинете клиники. [Объяснение сумм Cleveland Clinic](https://my.clevelandclinic.org/patients/billing-finance/understanding-your-bill) · [Правила отражения платежей Main Line Health](https://www.mainlinehealth.org/patient-services/patient-billing/frequently-asked-questions)

### 2. Подготовка к звонку

| Что видно из документов | Что показать человеку |
|---|---|
| Есть окончательный EOB и зачисленный платёж по визиту, сумма в счёте выше расчётной | **Call provider billing.** Номер на счёте клиники. Под рукой квитанция, дата визита и выписка. Текст подставляет настоящие суммы и просит письменный остаток. |
| Платёж зачислен после выпуска счёта | **Check your current balance.** Покажите обе даты. Если в кабинете клиники платёж по-прежнему не виден, предложите спросить расчётный отдел, когда он появится. |
| Окончательного EOB пока нет или страховая ещё рассматривает обращение | **Call your health plan.** Номер на страховой карте или EOB. Вопрос о статусе обработки и о том, где увидеть итоговую долю пациента. |
| Неясно, к какому визиту отнесли платёж, либо есть только общая сумма по семье | **Ask for a visit-level statement.** У расчётного отдела клиники запросить остаток по визиту и перечень зачисленных платежей. |

**Текст для учебного звонка.** “I paid $150 for my May 5 visit. My statement dated May 10 still shows $600. Could you check which visit my payment was applied to and send me the updated balance in writing?”

Во вкладке **MyChart / portal message** можно скопировать письменный запрос с датами и суммами из документов. При незавершённом EOB текст адресован страховой. После разговора сохраните дату звонка, обещанный остаток и срок ответа. Кнопка **Add Follow-Up Reminder (.ics)** скачивает событие на этот день. Если сотрудник обещал только перезвонить, пользователь может сохранить дату следующего контакта и продолжить дело. Обещанный остаток хранится отдельно от фактического остатка в новом документе.

### 3. Следующий счёт

1. При повторном посещении сайта человек открывает **Resume case**. Видит исходные суммы, запись о платеже и то, что ему сказали.
2. Вводит дату и полный остаток **следующего** счёта, подтверждает тот же визит и отмечает изменения со времени первой сверки. Если документы выпущены в один день, пользователь может отметить, какой из них исправленный. При новом EOB берётся обновлённая доля пациента. При дополнительном платеже исходная квитанция учитывается ровно один раз.
3. Приложение показывает предыдущий и новый выставленные остатки, актуальный расчётный остаток и разницу. Если условия прежние, рядом показывает и отклонение от обещанной суммы. Если EOB или платежи изменились, объясняет их вклад и сравнивает новый счёт с обновлённым расчётом. Когда условия или состав счёта не удаётся сопоставить, даёт вопрос для уточнения.
4. На экране остаются история обеих версий и следующий шаг. При нулевой разнице пользователь может нажать **Mark as resolved**. Повторное открытие или сохранение того же счёта не дублирует собственный платёж.

### 4. Цена и возврат

**Free** позволяет разобрать один визит до следующего счёта. **Plus** открывает печатный отчёт по делу с суммами, датами, вопросом, ответом клиники и результатом повторной сверки. Для MVP используйте предложенные в концепции **$9 в месяц или $59 в год** как гипотезу. На страницах проверки и цен кнопка **Unlock printable case report** открывает демооплату с заполненной тестовой картой. После **Unlock in Demo ($9.00 Test Checkout)** жюри печатает открытое дело через **Print / Save as PDF**. Оплата имитируется в браузере без списания. Семейная панель суммирует исходные положительные расхождения личных визитов и показывает историю каждого обращения.

Повод вернуться — обещанная дата ответа или следующий счёт. Первый показатель для проверки после запуска — доля людей, которые получили новый счёт и сверили его в сохранённом деле. Готовность платить и продлевать измеряйте отдельно. У Rekupr уже есть сверка EOB, письма и отслеживание обращений. Наше позиционирование для демо — проследить уже внесённый платёж от квитанции через обещание клиники до фактического нового остатка. [Функции Rekupr](https://rekupr.co/pricing)

## Как проверить результат и показать его за минуту

В **Quick demo scenarios** доступны четыре редактируемых примера: незачтённый платёж $150, платёж после выпуска счёта, возможный кредит $50 по новому EOB и ожидание решения страховой. Для ввода своих данных откройте **Paste text from EOB or clinic SMS**, проверьте распознанные поля и подтвердите недостающие сведения.

Учебный визит состоялся **5 мая**. В окончательном EOB от **8 мая** доля пациента **$600**, клиника зачислила **$150** по этому визиту **6 мая**, счёт от **10 мая** показывает **$600**.

| Ввод или действие | Ожидаемый результат |
|---|---|
| Открыть учебный визит | Расчётный остаток $450. Уточнить $150. Кнопка готовит звонок в клинику. |
| Изменить дату зачисления на 12 мая | На 10 мая расчётный остаток $600. Платёж $150 отмечен после даты счёта. Предложено проверить текущий остаток. |
| Вернуть 6 мая. Записать обещание клиники прислать остаток $450 к 15 мая. Открыть следующий счёт от 16 мая на $500 | При прежнем EOB и платежах к уточнению остаётся $50. Видны начальный остаток, обещанная сумма и новый документ. |
| Изменить новый счёт на $450 | Выставленный остаток $450, расхождение $0. Можно закрыть проверку. |
| Указать ещё один зачисленный платёж $50 перед вторым счётом и новый остаток $400 | Свои платежи за визит составляют $200, ожидаемый остаток $400, разница $0. Дополнительные $50 подписаны как платёж пациента. |
| Изменить долю пациента в новом EOB с $600 до $550 при одном платеже $150 и счёте $400 | Новый расчётный остаток $400, разница $0. Уменьшение доли пациента на $50 видно отдельно. |
| Указать другого поставщика, неизвестную сумму или минимальный платёж по рассрочке | Вместо суммы к оспариванию появляется запрос нужного документа. Неизвестное значение остаётся пустым. |
| Обновить страницу, открыть демодоступ к отчёту, распечатать, очистить дело | Дело восстанавливается до очистки. В отчёте суммы этого дела. После очистки открывается пустая форма. |

**Репетиция на 60 секунд.** 0–15 секунд — напарник открывает пример и показывает, откуда взялись $150. 15–30 — он открывает **Prepare my call** и сохраняет обещание $450. 30–45 — ты вводишь следующий счёт $500 и объясняешь оставшиеся $50. 45–60 — меняешь $500 на $450, показываешь нулевое расхождение и закрываешь проверку.
